Assembly Policies & the API Context

The pipeline vocabulary: the context tree that policies read and write, and the YAML shape of the policies you'll actually use.

Assembly skeleton

x-ibm-configuration:
  gateway: datapower-api-gateway
  assembly:
    execute:            # ← the pipeline: policies run top to bottom
      - policy-name:
          version: 2.0.0
          title: human label
          # …policy-specific fields
    catch:              # ← error handling, per error class
      - errors: [ ConnectionError ]
        execute:
          - …policies…
      - default:        # catches everything else
          - …policies…

The API context tree

Policies don't pass values to each other directly — they read and write one shared, JSON-like tree, addressed with dot notation (IBM Docs: context variables):

SubtreeHoldsExamples
request.*The original inbound request — treat as read-only.request.verb, request.headers.host, request.parameters.zip, request.body
message.*The payload flowing through the pipeline; what remains at the end becomes the client response. Policies mutate this.message.body, message.headers.content-type, message.status.code
api.*Metadata about the API and the matched operation, plus your properties.api.operation.path, api.properties.target-url
plan.* / client.*The subscribing plan and calling application.plan.name, client.app.name
error.*Populated inside catch blocks.error.status.code, error.message
your ownAnything you invent — e.g. an invoke's output or a set-variable target.geo.body, myflag

Access from YAML fields: $(api.properties.target-url) — the same $(…) you saw for properties. Access from GatewayScript: context.get('request.headers.x-zip') / context.set('myflag', true). Older samples use the v5-era apim.getvariable() API, which still works on the native gateway but context.* is the current idiom.

The policies you'll actually use

invoke — call a backend

- invoke:
    version: 2.0.0
    title: call-backend
    target-url: $(target-url)/branches
    verb: keep              # keep = same verb as inbound; or GET/POST/…
    output: backend_rsp     # optional: park response in a variable
                            # (omit → response becomes message.*)

The output trick is what makes orchestration possible: park the first backend's response, call a second backend, then merge — the pipeline keeps flowing instead of being overwritten.

set-variable — set/add/clear context values

- set-variable:
    version: 2.0.0
    title: defaults
    actions:
      - set: message.headers.x-frame-options   # overwrite or create
        value: DENY
      - add: message.headers.x-audit           # append
        value: $(client.app.name)
      - clear: message.headers.authorization   # remove

switch — branch the pipeline

- switch:
    version: 2.0.0
    title: route-by-operation
    case:
      - condition: ((request.verb==='GET')&&(api.operation.path==='/details'))
        execute:
          - …policies for this branch…
      - otherwise:
          - …fallback policies…

gatewayscript — arbitrary JavaScript on the gateway

- gatewayscript:
    version: 2.0.0
    title: reshape-response
    source: |
      var rsp = context.get('backend_rsp.body');
      context.message.body.write({
        id:   rsp.branchId,
        link: 'https://www.google.com/maps?q=' + rsp.lat + ',' + rsp.lng
      });

Node-style JS, synchronous-looking API, no filesystem. context.message.body.write(obj) sets the outgoing payload; context.get/set reads/writes the tree. Reference: IBM GatewayScript code examples.

The rest of the toolbox (recognize on sight)

PolicyUse
mapDeclarative field-to-field transformation between schemas. Powerful, verbose, best authored in the UI editor once and version-controlled forever after.
validateValidate message.body against a schema from your OpenAPI.
parseExplicitly parse the payload (JSON/XML) with limits — DoS protection knob.
operation-switchLike switch, but keyed directly on operation IDs.
xsltXSLT transform, for the XML-shaped corners of your estate.
ratelimit, throw, log, redact, jwt-validate, oauthWhat the names say; look them up when needed in the API Explorer / IBM docs.

Rules of thumb

SituationReach for
Plain proxysingle invoke, done
Set/strip headers, static valuesset-variable — cheaper and clearer than a script
Reshape a JSON payloadgatewayscript (or map if the mapping is large and schema-to-schema)
Different logic per operationoperation-switch / switch
Two backends, one responseinvoke with output: twice, then gatewayscript to merge
Backend down → friendly errorcatch on ConnectionError + set-variable/gatewayscript
Same custom steps in many APIsuser-defined policy (Lesson 6)
