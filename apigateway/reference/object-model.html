The Object Model

Every noun in API Connect, what it's for, and the CLI noun that manages it.

The hierarchy at a glance

API Cloud (Cloud Manager — platform ops, not your problem) └── Provider organization (pOrg) ← your team lives here ├── Drafts ← development artifacts, not on any gateway │ ├── Draft APIs = openapi.yml + x-ibm-configuration │ └── Draft Products = product.yaml referencing APIs, containing Plans │ └── Catalog (Sandbox, dev, prod …) ← a runtime environment; publish target │ bound to: gateway service(s) + optional Developer Portal ├── [Space] ← optional per-team partition (RBAC) ├── Product (staged/published) ← THE unit of publishing │ ├── Plan(s) rate limits, approval flow ◄─────┐ │ └── API(s) your openapi.yml, now live │ subscription └── Consumer organization │ └── Application (client id / secret) ──────────┘

The one rule that explains everything

You never publish an API. You publish a Product (which bundles APIs and Plans) into a Catalog (which is bound to a gateway). Apps subscribe to a Plan, never to an API directly. Once you accept this, every CLI command and REST path makes sense.

Object-by-object

ObjectWhat it isCLI noun
Provider org (pOrg)Home of an API-producing team. You must be a member to publish. Owns drafts and catalogs.orgs
CatalogAn isolated runtime environment (think dev, test, prod). Bound to one or more gateway services and optionally a Developer Portal. Every pOrg starts with a Sandbox catalog.catalogs
SpaceOptional partition inside a catalog so multiple teams can share one environment with separate permissions. Off by default.spaces
Draft APIYour OpenAPI 2.0/3.0 document plus the x-ibm-configuration extension (gateway type, assembly, properties). Lives in the pOrg, runs nowhere.draft-apis
Draft ProductA YAML file listing which APIs it bundles and which Plans it offers. The thing you stage/publish.draft-products
Product (in catalog)A published Product with a lifecycle: staged → published → deprecated → retired → archived. Only published Products serve traffic.products
PlanSubscription tier inside a Product: rate limits, burst limits, subscription approval. Not a standalone object — defined inside the Product YAML.—
Consumer orgAn organization of API consumers (app developers), registered per catalog, usually via the Developer Portal.consumer-orgs
ApplicationA consumer's app; holds client ID/secret credentials used to call APIs.apps
SubscriptionThe link: Application ↔ Plan (of a Product). This is what grants access.subscriptions
Gateway serviceThe DataPower runtime cluster that actually executes calls. Catalogs are bound to it; ops manage it in Cloud Manager.configured-gateway-services

CLI orientation map

Every toolkit command follows apic <noun>:<verb> plus --server, and --org / --catalog / --space to say where. Discover any noun's verbs with apic <noun> --help.

# who am I / where can I work
apic login --server $MGMT --realm provider/default-idp-2 --username $USER
apic orgs:list      --server $MGMT
apic catalogs:list  --server $MGMT --org $ORG

# development (drafts, in the pOrg)
apic draft-apis:list      --server $MGMT --org $ORG
apic draft-products:list  --server $MGMT --org $ORG

# runtime (published, in a catalog)
apic products:list  --server $MGMT --org $ORG --scope catalog --catalog $CAT
apic products:clone --server $MGMT --org $ORG --scope catalog --catalog $CAT  # download everything

# publish
apic products:publish my-product.yaml --server $MGMT --org $ORG --catalog $CAT

Note: exact flags vary slightly by fixpack — trust --help on your installation over any blog post, including this one.

Glossary

TermMeaning
Management server / platform API endpointThe host the toolkit and REST API talk to (--server). Same backend the API Manager UI uses.
Realm / identity providerWhich user registry you authenticate against, e.g. provider/default-idp-2. List with apic identity-providers:list --scope provider.
x-ibm-configurationIBM's OpenAPI extension holding everything the gateway needs: gateway type, security, properties, and the assembly.
AssemblyThe "custom pipeline": an ordered execute array of policies the gateway runs per request (invoke, map, gatewayscript, validate…).
PolicyOne processing step in an assembly. User-defined policies package reusable custom steps.
DataPower API Gateway vs v5-compatibleTwo gateway types in v10. The native API Gateway is current; v5c exists for migration. They support different policies — check which your catalog uses.
ToolkitThe apic CLI binary. It is a thin wrapper over the Platform REST API (see it with --debug).
