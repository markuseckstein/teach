Lesson 6: Tasks → Analyze → Implement

≈40 minutes, hands-on · closes the loop started in Lesson 4 — you need its spec + plan (ideally inside the Lesson 5 umbrella)

The win you're after

The bookmark feature from Lesson 4, implemented end-to-end by Copilot from tasks.md — with the OpenAPI contract flowing from specs/…/contracts/ into both repos' generators, the way it will at work.

The one idea: tasks.md is an execution contract

The tasks template isn't a to-do list — it's structured for machine execution:

  • Format [ID] [P?] [Story] + exact file paths. [P] marks tasks parallelizable (different files, no dependencies); [Story] ties every task to a user story from the spec.
  • Story-grouped phases. Setup → Foundational (blocking — nothing proceeds without it) → one phase per user story, each independently implementable and testable. This is why Lesson 4 insisted P1 must stand alone: the phases inherit that property, so you can stop after P1 and still have shipped something.
  • Checkpoints between phases — natural places to review, commit, and (for large features) restart the agent with fresh context.
The trap: tests are optional by default The template says it plainly: "Tests are OPTIONAL — only include them if explicitly requested in the feature specification." But your Lesson 3 constitution's Article III says every FR maps to a test. Those two collide — and the resolution is the system working: either your spec requests tests (say it in /speckit.specify or add it via clarify), or /speckit.analyze should flag the gap as a constitution violation. If tasks.md arrives test-free and analyze stays silent, you've found a hole worth fixing upstream, not by hand-editing tasks.

Analyze: the last cheap checkpoint

Two properties, verified in the command definition: it is strictly read-only (it reports; you decide), and constitution conflicts are automatically CRITICAL — the fix must adjust spec/plan/tasks, never dilute or reinterpret the principle. If a principle itself is wrong, that's an explicit constitution amendment, outside analyze. Your constitution really is the supreme court of this workflow.

Do it

Step 1 — Generate the task list

/speckit.tasks

Audit before proceeding (the checklist has the full list):

  1. Every task has an exact file path; story phases match the spec's P1/P2/P3.
  2. Test tasks exist for every FR — if not, see the trap above.
  3. Contract-sync tasks exist: something must carry specs/001-*/contracts/openapi.yaml into the backend's and frontend's generator inputs and run generation (mvn generate-sources / your npm run generate). If the plan didn't produce such tasks, tell the agent: "Add tasks: sync the contract into backend and frontend generator configs and regenerate — per constitution Article I, no hand-written API code."

Step 2 — Analyze, and take it seriously

/speckit.analyze

Read the report end-to-end once. Expect findings — coverage gaps (an FR no task implements), terminology drift, constitution conflicts marked CRITICAL. Fix the artifacts it names (re-run /speckit.clarify or edit the spec/plan via the agent), then re-run analyze until CRITICALs are gone. Resist the urge to skip this on a green-looking feature — it's minutes now against a refactor later.

Step 3 — Implement, phase by phase

/speckit.implement Complete Phase 1 and Phase 2 only, then stop for review.

For anything non-trivial, phase-wise beats one-shot: context stays small, and each checkpoint is a commit you actually reviewed. Then continue story-by-story (Implement Phase 3 (User Story 1) only…). After the last phase:

/speckit.converge

which verifies completion and lists remaining work.

Verify the mission-critical bit: in the umbrella, check that backend controllers implement generated server interfaces and the Angular code calls the generated client — git -C backend diff --stat / git -C frontend diff --stat should show generated sources changing alongside handlers, and nothing hand-edited inside generated output directories. That's Article I holding under fire.

Check yourself

1. tasks.md arrives with no test tasks. What does the template say happened?
2. What is /speckit.analyze forbidden from doing?
3. Analyze flags a CRITICAL constitution conflict. The sanctioned fix is…
4. In tasks.md, what does the [P] marker on a task mean?
