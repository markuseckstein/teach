Lesson 2: The Toolchain, Behind the Proxy

≈25 minutes, hands-on at your Windows machine · builds on Lesson 1: The SDD Loop

The win you're after

By the end: specify init has scaffolded a scratch project, and Copilot CLI answers you — both from Git Bash, both through the corporate proxy. That's the entire toolchain for every later lesson.

The one idea

Your toolchain is three different runtimes, and an SSL-inspecting proxy breaks each one separately:

ToolRuntimeTrusts the corporate CA when…
specify (via uvx)Rust — bundled Mozilla rootsUV_SYSTEM_CERTS=true → Windows cert store
gitGit for Windows — OpenSSL by defaulthttp.sslBackend schannel → Windows cert store
Copilot CLINode.jsNODE_EXTRA_CA_CERTS=…corp-ca.pem

The error is always some variant of "self-signed certificate in chain"; the knob is always runtime-specific. Once you see the pattern, no proxy failure in any tool will surprise you again. IT already pushed the corporate CA into the Windows certificate store via group policy — so the first two fixes just point the tool at what's already there (uv TLS docs).

Do it — at your machine, in Git Bash

Step 1 — Proxy address, once, for everything

cat >> ~/.bashrc <<'EOF'
export HTTP_PROXY="http://proxy.company.example:8080"   # ← your real proxy
export HTTPS_PROXY="$HTTP_PROXY"
export NO_PROXY="localhost,127.0.0.1,.company.example"
export http_proxy="$HTTP_PROXY" https_proxy="$HTTPS_PROXY" no_proxy="$NO_PROXY"
export UV_SYSTEM_CERTS=true
EOF
source ~/.bashrc

Lowercase twins included deliberately — some tools read only those. Don't know the proxy address? In PowerShell: netsh winhttp show proxy, or ask a colleague for the PAC-file address.

Step 2 — Install uv, teach git the Windows trust store

winget install --id=astral-sh.uv -e     # enterprise-friendly; avoids the curl-installer cert problem
git config --global http.sslBackend schannel
exec bash -l                             # new shell so PATH + env are fresh
uv --version                             # ✓ expect a version string

Step 3 — Bootstrap a scratch project with specify

cd ~ && uvx --from git+https://github.com/github/spec-kit.git \
  specify init sdd-playground --ai copilot --script sh

Verify: ls sdd-playground/.github/prompts/ shows speckit.*.prompt.md files, and sdd-playground/.specify/scripts/bash/ exists (that's what --script sh bought you — PowerShell scripts would be useless in Git Bash). If it fails with UnknownIssuer: Step 1's UV_SYSTEM_CERTS isn't in effect — echo $UV_SYSTEM_CERTS.

Step 4 — Copilot CLI

Two Windows quirks, straight from the official README: it requires PowerShell 6+ installed (Windows ships 5.1 — install with winget install Microsoft.PowerShell), even though you'll drive it from Git Bash. And if your org admin has disabled Copilot CLI in enterprise policy, no local fix will help — that's an IT ticket, not a config problem.

winget install Microsoft.PowerShell      # only if pwsh -v fails
winget install GitHub.Copilot            # or: npm install -g @github/copilot (needs Node 22+)
export NODE_EXTRA_CA_CERTS=/c/certs/corp-ca.pem   # see cheat sheet for getting this PEM
copilot                                  # then: /login and follow the device-code flow

Verify: inside copilot, ask it "what directory am I in?" — a sensible answer proves auth and proxy traversal. Used npm instead? npm needs its own knobs first: npm config set proxy/https-proxy/cafile — see the proxy cheat sheet.

Step 5 — Confirm VS Code sees Spec Kit

cd ~/sdd-playground && code .

Verify: in Copilot Chat (agent mode), type /speckit. — the command list from Lesson 1 should autocomplete. Don't run them yet; that's Lesson 3 (constitution).
