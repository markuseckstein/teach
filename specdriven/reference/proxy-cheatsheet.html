Corporate Proxy Cheat Sheet

Reference · every tool in the SDD toolchain, and which knob makes it trust the proxy

The one rule SSL-inspecting proxies re-sign every HTTPS connection with the corporate CA. Each runtime keeps its own trust store, so each tool must be told about that CA separately. One error message — self-signed certificate in certificate chain / UnknownIssuer — many knobs.

Proxy address (all tools)

In ~/.bashrc (Git Bash reads it):

export HTTP_PROXY="http://proxy.company.example:8080"
export HTTPS_PROXY="$HTTP_PROXY"
export NO_PROXY="localhost,127.0.0.1,.company.example"
# lowercase twins — some tools only read these
export http_proxy="$HTTP_PROXY" https_proxy="$HTTPS_PROXY" no_proxy="$NO_PROXY"

Trust knobs per tool

ToolRuntimeKnobNotes
uv / uvx (runs specify)Rust (own TLS)export UV_SYSTEM_CERTS=trueUses the Windows cert store, where IT's GPO already put the corporate CA. Default is bundled Mozilla roots, which do not know your proxy. Older docs call this --native-tls / UV_NATIVE_TLS. Alternative: SSL_CERT_FILE=/c/certs/corp-ca.pem (overrides entirely — bundle must then contain public roots too).
git (clones spec-kit templates; branch scripts)Git for Windows (OpenSSL by default)git config --global http.sslBackend schannelSwitches git to the native Windows TLS stack → corporate CA picked up automatically. Alternative: git config --global http.sslCAInfo C:/certs/corp-ca.pem. Proxy: git honors HTTPS_PROXY, or set git config --global http.proxy.
Copilot CLINode.jsexport NODE_EXTRA_CA_CERTS=/c/certs/corp-ca.pemExtra certs — added on top of Node's bundled roots, so no need to merge public CAs. Honors HTTP(S)_PROXY. Windows prerequisite: PowerShell 6+ installed, even when you launch it from Git Bash.
npm (installs Copilot CLI)Node.jsnpm config set proxy $HTTP_PROXY
npm config set https-proxy $HTTPS_PROXY
npm config set cafile C:/certs/corp-ca.pem		npm does not read NODE_EXTRA_CA_CERTS for its own registry traffic — it needs cafile.
Copilot in VS CodeElectron/NodeSettings → http.proxy; corporate CA usually picked up from OS store via http.systemCertificates (default on)Plus NODE_EXTRA_CA_CERTS if the extension host still complains.

Getting the corporate CA as a PEM file

# From Git Bash — show what the proxy actually presents, save the chain:
openssl s_client -connect api.github.com:443 -showcerts </dev/null 2>/dev/null \
  | sed -n '/BEGIN CERT/,/END CERT/p' > /c/certs/corp-ca.pem

Better: ask IT for the official root-CA bundle — the snippet above grabs the presented chain, which may omit the root. Store it somewhere stable like C:\certs\; several knobs reference it.

Domains to allowlist (for IT tickets)

github.com · api.github.com · *.githubusercontent.com · *.githubcopilot.com — see GitHub's network settings doc for the authoritative list.
