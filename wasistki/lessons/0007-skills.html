Lektion 7 · Teil III — Die Werkzeuge

Skills: Können zum Weitergeben

Ein guter Prompt ist ein guter Einfall. Ein Skill ist ein Verfahren — man kann es aufheben, verbessern und einer Kollegin geben. Das ist ein größerer Unterschied, als es klingt.

10 Minuten Ziel: verstehen, was ein Skill leistet Setzt Lektion 6 voraus

Sie haben irgendwann einen richtig guten Chat gehabt. Sie haben eine halbe Stunde gebraucht, um dem Modell zu erklären, wie ein Elternbrief an Ihrer Schule klingen muss — Anrede, Länge, Tonfall, was nie hineingehört. Am Ende kam etwas heraus, das Sie ohne Änderung verschicken konnten.

Vier Wochen später schreiben Sie den nächsten Elternbrief. Der Chat von damals ist irgendwo in der Liste, Sie finden ihn nicht, und selbst wenn — er ist vollgestellt mit dem alten Thema (Lektion 3). Sie fangen wieder bei null an.

Das eigentliche Problem beim Arbeiten mit Chatbots ist nicht die Qualität der Antworten. Es ist, dass nichts davon bleibt.

Ein Skill ist ein Ordner mit einer Textdatei

Wichtig Ein Skill ist kein Programm. Es ist eine Textdatei mit Anweisungen in normaler Sprache. Wenn Sie eine Vertretungsanweisung für eine Kollegin schreiben können, können Sie einen Skill schreiben.

Genau dafür wurden Skills erfunden. Die Definition des offenen Standards ist knapp:

„Im Kern ist ein Skill ein Ordner, der eine Datei SKILL.md enthält. Diese Datei enthält Metadaten (mindestens name und description) und Anweisungen, die einem Agenten sagen, wie er eine bestimmte Aufgabe erledigt.“ agentskills.io — der Standard wurde von Anthropic entwickelt und im Dezember 2025 als offener Standard veröffentlicht

Optional liegen im selben Ordner noch Vorlagen, Beispieldateien oder kleine Hilfsprogramme. Für Ihre Zwecke reicht aber fast immer die eine Textdatei. So könnte die für Ihren Elternbrief aussehen: 

---
name: elternbrief
description: Schreibt einen Elternbrief im Stil unserer Schule.
---

Frag mich zuerst nach Anlass, Adressatenkreis und Termin,
falls ich das nicht schon gesagt habe.

Regeln für jeden Brief:
- Anrede: "Liebe Eltern und Erziehungsberechtigte,"
- höchstens eine halbe Seite
- keine Behördensprache, keine Substantivketten
- das Datum und die Uhrzeit immer fett und in einer eigenen Zeile
- kein Konjunktiv bei Aufforderungen
- Schlussformel: "Mit freundlichen Grüßen"

Schreib mir am Ende zusätzlich einen Zweizeiler für die
Klassenchat-Gruppe, mit derselben Information.

Zeig mir zwei Varianten: eine sachliche und eine wärmere.

Das ist alles. Kein Code, keine geschweiften Klammern, nichts zu installieren. Und ab jetzt sagen Sie nur noch „schreib einen Elternbrief zum Wandertag am 12. Mai“ — den Rest weiß der Agent.

Prompt oder Skill — der Unterschied

Warum man viele Skills haben kann, ohne den Schreibtisch zu verstopfen

Hier schließt sich der Kreis zu Lektion 3. Wenn Sie dreißig Skills haben und alle dreißig ständig auf dem Schreibtisch lägen, wäre der voll, bevor Sie ein Wort getippt haben. Deshalb funktionieren Skills in drei Stufen — der Standard nennt es progressive disclosure, „schrittweises Aufdecken“:

Zwei Skills zum Anschauen

Der Entwickler Matt Pocock veröffentlicht eine Sammlung von Skills, die einen guten Eindruck davon gibt, was jenseits von Textbausteinen möglich ist. Zwei davon sind auch für Nicht-Programmierer unmittelbar nützlich.

teach — mehrere Sitzungen, ein Lernstand

Beschreibung im Original: „Teach the user a new skill or concept over multiple sessions, using the current directory as a stateful teaching workspace.“

Der Skill legt in einem Ordner an, was ein Chat nicht behalten kann: warum Sie das Thema lernen wollen, was Sie schon verstanden haben, welche Quellen vertrauenswürdig sind, und die fertigen Lektionen. Beim nächsten Mal liest der Agent diesen Ordner und weiß, wo Sie stehen — obwohl das Modell selbst nach wie vor zustandslos ist.

Sie halten das Ergebnis gerade in der Hand

Dieser Kurs — die Lektionen, die Diagramme, das Glossar, die Datei mit dem Lernstand — ist mit genau diesem Skill entstanden. Schauen Sie sich ruhig den Ordner an, in dem er liegt. Das ist kein Kunststück eines besonders klugen Modells, sondern das Ergebnis eines Verfahrens, das jemand einmal aufgeschrieben hat.

grill-me — sich das eigene Vorhaben zerpflücken lassen

Beschreibung im Original: „Get relentlessly interviewed about a plan or design until every branch of the design tree is resolved.“ — sinngemäß: unerbittlich zu einem Plan befragt werden, bis jeder offene Punkt geklärt ist.

Der Skill dreht die übliche Richtung um. Sie fragen nicht, Sie werden gefragt. Und zwar so lange, bis jede Lücke in Ihrem Plan sichtbar ist. Für eine Lehrkraft ist das erstaunlich brauchbar:

  • „Ich plane eine Projektwoche zum Thema Wasser“ — und Sie werden dreißig Minuten lang zu Aufsicht, Budget, Schlechtwettervariante, Differenzierung und Elterninformation befragt, bis der Plan steht.
  • „Ich will die Leistungsbewertung in meinem Fach umstellen“ — und jemand sucht systematisch nach den Fällen, in denen Ihr neues System unfair wird.
  • „Ich habe morgen ein schwieriges Elterngespräch“ — und Sie üben es gegen jemanden, der wirklich nachbohrt.

Der Nutzen entsteht nicht daraus, dass der Agent etwas weiß, das Sie nicht wissen. Er entsteht daraus, dass er unbequem und ausdauernd ist, ohne Ihnen gegenüber Rücksicht nehmen zu müssen. Das kann sonst niemand in Ihrem Kollegium leisten — nicht aus Unwillen, sondern aus Zeitmangel und Höflichkeit.

Wie man diese Skills bekommt

Sie brauchen ein Werkzeug, das Skills unterstützt — Claude Code oder Cowork etwa, aber auch viele andere (Lektion 8). In Claude Code installiert man die Sammlung mit einem Befehl: 

claude plugins install mattpocock-skills

Danach ruft man einen Skill mit einem Schrägstrich auf, etwa /grill-me. Eigene Skills legt man an, indem man einen Ordner mit einer SKILL.md anlegt — mehr passiert dabei wirklich nicht.

Kurz nachgedacht

Abrufübung

Sie haben dreißig Skills installiert. Was liegt beim Start eines Gesprächs davon im Kontextfenster?

  • Alle dreißig vollständig, damit der Agent sofort zugreifen kann.
  • Von jedem nur Name und Beschreibung, sonst nichts.
  • Gar nichts — Skills werden erst beim Aufruf überhaupt bemerkt.
  • Die fünf zuletzt benutzten vollständig, die übrigen gar nicht.

Das ist die erste Stufe des schrittweisen Aufdeckens. Der Agent hat quasi das Inhaltsverzeichnis vor sich — genug, um zu erkennen, wann ein Skill einschlägig ist, und wenig genug, dass dreißig Stück kaum Platz kosten. Erst wenn Ihre Aufgabe zu einer Beschreibung passt, wird die vollständige Anweisung nachgeladen.

Abrufübung

Was ist der entscheidende Vorteil eines Skills gegenüber einem gespeicherten Prompt in einer Notizdatei?

  • Der Skill formuliert seine Anweisungen für das Modell wirksamer.
  • Der Skill funktioniert auch dann, wenn das Modell gewechselt wird.
  • Der Agent findet und benutzt ihn von selbst, im richtigen Moment.
  • Der Skill braucht deutlich weniger Platz im Kontextfenster als Text.

Ein Prompt in einer Notizdatei erfordert, dass Sie daran denken, ihn heraussuchen und einfügen. Genau daran scheitert es im Alltag. Ein Skill wird vom Agenten selbst erkannt und geladen, sobald die Aufgabe dazu passt. Die Arbeit, an das Verfahren zu denken, wandert von Ihnen zum Werkzeug — und das ist der ganze Gewinn.

Ohne nachzuschlagen

Denken Sie an eine Aufgabe, die Sie in diesem Schuljahr mindestens fünfmal machen werden und die jedes Mal gleich abläuft. Schreiben Sie in fünf Stichpunkten auf, was dabei die Regeln sind. Das ist bereits ein Skill — es fehlt nur noch der Dateiname.

Primärquelle für diese Lektion

agentskills.io — die Spezifikation des offenen Standards. Ungewöhnlich gut lesbar für ein Normdokument; die Startseite allein beantwortet die meisten Fragen. Wer die Beispiele sehen will: Matt Pococks Sammlung liegt offen auf GitHub, und man kann jeden Skill als schlichten Text lesen.

Fragen Sie nach. Die beste Frage hier ist praktisch: „Ich mache regelmäßig Folgendes … — schreib mir daraus einen Skill.“ Das dauert fünf Minuten und Sie haben etwas, das Sie behalten.
